# `env/` – runtime configuration template

The runtime services expect a folder `ReHoster/env/` with secrets, certificates and service configurations.
That folder is not part of the repository (it contains secrets); this folder is a template for it.

## Quick start

```bash
cd ReHoster
./env.example/init_env.sh <your host name> [<your TURN host name>]
```

The script copies the template to `env/` (every `.env.example` becomes `.env`), creates
`ReHoster/docker-compose.yaml` from `docker-compose.example.yaml`, replaces `example.org` with your host
name, sets random passwords for Pi-hole and TURN, and creates self-signed certificates. Replace the certificates with
trusted ones (e.g. Let's Encrypt) if the web front end is reachable from outside.

## Resulting structure

```text
env/
├── .env                          (from .env.example) environment for the emulator and Pi-hole containers (TZ, WEBPASSWORD, TURN)
├── adb_streamer/
│   ├── fmd.cert                  TLS certificate of the ADB streaming service
│   ├── fmd.key
│   └── .env                      optional adb_streamer service (compose profile "streaming")
├── coturn/
│   └── turnserver.conf           TURN relay for the WebRTC emulator display (credentials = TURN in .env)
├── envoy/
│   ├── init_envoy.sh             waits for certificate + envoy.yaml, then starts envoy
│   ├── <host>/
│   │   ├── certificate.pem       TLS certificate of the gRPC-web proxy (mounted at /etc/envoy/certs/)
│   │   └── privkey.pem
│   └── envoy.yaml                generated by create_docker_startup_scripts.py (one route per emulator)
├── mitmproxy/
│   ├── .env
│   └── config.yml                mitmproxy options; CA certificate in ../toolbox/ca_certificates/
├── nginx/
│   ├── nginx.conf
│   ├── app.conf                  web front end (TLS termination), mounted as conf.d/default.conf
│   ├── public/                   static web content
│   └── ssl/live/<host>/
│       ├── fullchain.pem
│       └── privkey.pem
└── pihole/
    └── .env                      Pi-hole settings (password, time zone); data is stored in ReHoster/pihole-data/
```

## Variables in `.env` (template: `.env.example`)

| Variable | Used by | Meaning |
|---|---|---|
| `TZ` | all containers | time zone, e.g. `UTC` |
| `WEBPASSWORD` | Pi-hole | password of the Pi-hole web interface / API |
| `TURN` | emulator containers | command that prints the WebRTC ICE configuration; user, password and host must match `coturn/turnserver.conf` |

Keep one `KEY=VALUE` per line: `docker_spawn.py` parses the file line by line.

## Blocklists

Load the frozen feeds from `DataSources/Blocklists/Blocklists.zip` into Pi-hole (`00_all_blocklist_urls.txt`
lists the original URLs) so that `pihole/gravity.db` matches the configuration used in the paper.

## Services (`docker-compose.example.yaml`)

| Service | Address | Role |
|---|---|---|
| `pihole` | 172.31.250.2 | DNS resolver of all emulators, applies the blocklists, logs queries |
| `adb_streamer` | 172.31.250.3 | optional live view (`--profile streaming`; source not part of this artifact) |
| `mitmproxy` | 172.31.250.4 | traffic interception (transparent, SOCKS5, regular, WireGuard) |
| `envoy` | host :443 | gRPC-web proxy to the emulators |
| `nginx` | host :80, :8443 | web front end |
| `coturn` | host network | TURN relay for WebRTC |

Networks `project_frontend` and `project_android` (172.31.250.0/24, emulators from .128/25) are created
by compose and used by `consumer.py`. Start everything with `docker compose up -d`.
