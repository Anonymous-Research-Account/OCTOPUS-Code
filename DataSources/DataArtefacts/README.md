**Where to put the files.** Download all files from [https://zenodo.org/records/24012262](https://zenodo.org/records/24012262) into **one** folder `data/` in the repository
root, without renaming or unpacking them. Level A reads this folder directly
(`DataAnalysis/paper_results/run_all.sh ../../data`). For the notebooks (Level B), run
`DataAnalysis/link_data.sh ../data`, which links each file into the folder given in the last column. The MD5
checksums are listed in [`zenodo_md5.txt`](zenodo_md5.txt). See `REPRODUCE.md`, sections 1–3.

**Not released.** The Pi-hole query database (`pihole-FTL.db`) and the raw packet captures are not part of the
dataset. The Pi-hole database is the unfiltered DNS log of the measurement network and also contains client
addresses, timestamps and queries of the measurement infrastructure that are unrelated to the experiments.
All information used in the paper is included in released files: per-packet metadata with UID/package
attribution and resolved destination domain in `app_traffic.parquet`, the Pi-hole query counts per blocklisted
domain in `blocked_domains.parquet`, and the blocklist feeds in `DataSources/Blocklists/Blocklists.zip`. The raw packet captures and the Pi-hole databases are needed only by notebooks 02, 03 and 05; all paper results are computed from the released files (Level A).

Together, these files provide the metadata, static-analysis results, dynamic execution summaries, and network-traffic observations required to reproduce and extend the analyses presented in the paper. The dataset is organized to preserve the relationships between firmware samples, extracted applications, static-analysis findings, runtime execution results, and observed network communications.
