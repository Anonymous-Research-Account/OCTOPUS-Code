# OCTOPUS Anonymous Artifact Repository

This repository contains the source code and data-analysis components used in our anonymous submission. The repository is organized into three main components corresponding to the firmware analysis, dynamic re-hosting, and experimental data-analysis stages of our pipeline.

## Repository Structure

```text
.
├── DataSources/
│   └── Original sources (device images and blocklists) for the used dataset
│
├── FMD/
│   └── Modified FirmwareDroid source code
│
├── ReHoster/
│   └── FMD-AECS re-hosting framework
│
└── DataAnalysis/
    └── Data-analysis scripts and artefacts

```

**FMD/**

The folder contains the modified FirmwareDroid (FMD) implementation used in our experiments.

The modifications extend the original FirmwareDroid functionality to support the firmware processing and application extraction required by our experimental pipeline.


**ReHoster/**

This directory contains contains the modified FMD-AECS re-hosting implementation used in our experiments.

The re-hosting framework prepares and executes extracted Android firmware components in the virtualized analysis environment. The modifications support the automated re-hosting and dynamic analysis workflow described in the paper.


**DataAnalysis/**

This directory contains the scripts (Jupiter Notebooks) used to analyze the artefacts generated by the FMD and the ReHoster components.

The analysis code processes the experimental results and generates the quantitative results presented in the paper, including the static and dynamic analysis results.


## Experimental Workflow

The three components correspond to the main stages of our experimental pipeline:

```text
Firmware Images
      │
      ▼
     FMD (Pre-Processing)
      │
      │ Firmware processing and application extraction
      ▼
  ReHoster (Pre-Processing)
      │
      │ Automated re-hosting 
      ▼
  Emulation -> Dynamic Analysis (Runtime Testing)     
      │
      │ Emulation and UI Stimulation 
      ▼ 
Experimental Artefacts
      │
      ▼
Data-Analysis (Post-Processing)  
      │
      ▼
Results reported in the paper
```

## Reproducibility

**Start here: [`REPRODUCE.md`](REPRODUCE.md)** is a step-by-step guide to set up the artifact and reproduce the results. All numbers in the paper can be reproduced on a laptop in a few minutes from the released data (`DataAnalysis/paper_results/run_all.sh`).

Quick start (Level A, details in `REPRODUCE.md`):

```bash
mkdir -p data      # download app_traffic.parquet, static_analysis.parquet, coverage.csv and blocked_domains.parquet
                   # from https://zenodo.org/records/24012262 into this folder (repository root)
cd DataAnalysis/paper_results
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
./run_all.sh ../../data
```

Each directory contains the code and configuration required for its respective stage of the experimental pipeline. Component-specific setup and execution instructions are provided in the corresponding directories where applicable.

The artifact depends on external software (e.g., FirmwareDroid) and a dataset of Android device images. Components that cannot be redistributed are not included in the repository; where applicable, the repository provides the corresponding code, configuration, or instructions required to reproduce the relevant processing steps.
